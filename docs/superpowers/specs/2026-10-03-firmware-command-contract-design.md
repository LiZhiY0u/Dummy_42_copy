# 下位机命令契约与功能框架同步设计

日期：2026-10-03。状态：用户要求继续下位机开发，按本范围形成[实施计划](../plans/2026-10-03-firmware-command-contract.md)，计划待评审；未进入产品实现。

## 1. 目标与事实边界

用户目标：根据上位机进度同步完善下位机功能框架。已确认第一轮范围为统一命令契约、载荷校验、能力声明及后端扩展入口，保留实际控制执行路径。

当前Qt实际界面以连接、信息、状态和STOP为主；协议及通用核心已定义20个请求。P9接入9个请求，另11个直接返回UNSUPPORTED。Qt与通用核心有完整载荷校验，P9未实现请求的载荷校验存在缺口。

本轮成功条件是契约一致、拒绝行为可预测、执行边界不变，不是增加可用运动功能。旧诊断固件实测及既有软件通过记录不能作为本轮实现的验证结果。

## 2. 选择与非目标

采用“提取无平台命令契约，接入现有分发路径”。它解决契约分叉，不改变邮箱执行模型。

不采用直接复用通用同步CommandBackend替换P9分发：通用接口返回即代表操作完成，P9使用控制周期邮箱与完成回收，不能同步等待或提前返回OK。

不在本轮一次接入运动、参数存储与校准：这些需要独立的控制、Flash及任务生命周期验收。

明确不做：新运动命令执行、参数读写/保存后端、校准任务、任务/故障事件、Qt新页面、新线格式、新状态码、新定时器或IRQ、HAL/链接脚本/Keil工程修改、硬件烧录、使能或运动、提交推送。

## 3. 契约层职责与接口

新增C++11无平台头文件command_contract.h，命名空间stepper::contract。只依赖固定宽度整数和size_t，不依赖Qt、Frame、HAL、Motor或邮箱。

定义三个逻辑入口：

- describe(command)：返回只读命令描述或空指针。描述包括命令号、校验规则及功能组；未知号不得落入宽泛区间判断。
- validatePayload(command, payload, length)：只校验命令与载荷，返回现有状态0/2/3/4；成功只表示载荷合法，绝不表示后端已执行。
- capabilities(support)：从显式目标支持清单计算现有能力位；描述存在不等于目标支持。

描述表覆盖20个请求，不将事件和遥测号当成请求。规则及字段以[协议基线](../../protocol/serial-v1.md)为准，不在这里重新复制完整线布局。参数schema1的15项编号、类型、重复检测与范围一起迁入契约层。

validatePayload应先验证精确长度，再读取字段；128B以上返回BAD_PAYLOAD。非零长度且空指针返回BAD_PAYLOAD。零长度合法请求可使用空指针。未知请求返回UNKNOWN_CMD。任务ID非零、正值/有符号边界、遥测周期及参数范围与当前Qt规则一致，不新增设备运行限值。

描述只提供静态元数据，不使用运行时注册、虚拟后端注册或函数指针调度。后端扩展入口是显式目标支持清单和现有执行分支；没有后端的项禁止填写占位成功实现。

## 4. 两仓库的单一来源与边界

权威源文件放在上位机工作区firmware/core/command_contract.h。P9 Uart/command_contract.h为同一文件的版本化分发副本，不独立维护。

现有校验脚本增加逐字节一致性检查，作为联调验收门槛；不依赖绝对用户目录、符号链接或构建时从另一仓库读取源码。脚本通过明确的固件目录参数定位副本。两个仓库仍可分别编译；文件不一致时联调检查必须失败，不能悄悄继续。

Qt ProtocolMessages保留帧TYPE、SEQ、载荷上限及HELLO/普通请求的会话检查，然后调用契约载荷校验。参数校验公开入口也使用同一规则。

通用CommandDispatcher保留会话、缓存、水位及同步Backend接口，仅替换重复的命令/参数校验逻辑。本轮不修改其执行接口。

P9 uart_protocol在现有会话及事务检查之后统一调用契约校验，然后按显式目标支持清单判定UNSUPPORTED，再进入既有执行分支。删除knownButUnsupported的区间识别及重复载荷校验；保留完成回收和应答格式。

## 5. 数据流与错误优先级

P9处理顺序保持：帧结构 → 当前会话 → 缓存/待处理去重及序号水位 → 命令载荷校验 → 目标支持 → 状态/邮箱提交 → 控制周期执行 → 主循环完成应答。

HELLO仍保留新token接管例外及运行/校准禁止接管条件。校验不应提前改变其缓存作用域和pending映射。

重复的已缓存请求仍返回原应答；同SEQ内容变化仍返回SEQ_CONFLICT。错误会话仍优先返回BAD_SESSION。不能为了对齐校验把错误请求提交到控制邮箱。

行为修正：未实现命令载荷错误先返回BAD_PAYLOAD或OUT_OF_RANGE，合法载荷才返回UNSUPPORTED；未知命令返回UNKNOWN_CMD。该修正落实现有基线的“校验先于能力”顺序，保持V1/revision1、字段和状态码不变。

拒绝请求沿用现有sendAndRemember及事务水位语义，不改变拒绝请求的序号消费规则。TYPE/SEQ/帧结构非法仍按当前帧层行为丢弃，不生成新响应。

## 6. 目标支持与能力声明

P9支持清单保留9项：HELLO、GET_INFO、GET_STATUS、HEARTBEAT、ENABLE、DISABLE、STOP、CLEAR_FAULT、TELEMETRY_CONFIG。

其余11项在载荷合法后仍返回UNSUPPORTED。ENABLE当前模式及安全Gate限制保持不变，不能由ENABLE存在推出MOVE_ABS/SET_VELOCITY/SET_CURRENT可用。

能力映射按现有协议位定义。当前P9期望仍为0x180（清故障与遥测）；测试必须将其作为独立断言，而不能只调用被测capabilities函数生成期望值。组合功能的能力只有在该位所需命令都具备实际后端时才能置位。

本轮增加后端扩展说明：新增功能须同时提供目标支持项、实际执行/完成反馈、契约测试、能力映射测试及验收记录。不得只修改描述或支持位。

## 7. ISR、内存与栈约束

契约校验只在主循环/主机代码调用，不放入UART或控制中断。契约层不得操作硬件、刷新心跳、修改状态、等待执行或发送数据。

不使用动态分配、递归、异常、RTTI、日志格式化或阻塞等待。不新增Frame副本/全载荷局部数组。参数重复检测最多使用15个u16局部ID，并测量其实际调用栈影响；描述和支持清单为只读常量。

维持现有队列、缓存容量、1024B栈及既有Flash/RAM区域，不增加链接区域或栈配置。840B是之前正常候选的估算，不是本轮结果。新构建必须重算完整调用链且不超过1024B；不能只用头文件编译成功替代栈审核。

本轮不修改IRQ优先级、控制周期或超时，不设未经测量的微秒耗时指标。运行栈高水位、ISR耗时和正常模式硬件验收仍单独待验证。

## 8. 验收标准

1. 20个请求每个载荷长度0～128均有跨Qt/契约层对比用例；覆盖合法非零会话，另外测试帧/会话错误优先级。长度矩阵之外必须有每条命令独立合法向量，不能让“全部拒绝”通过对比。
2. 独立断言错误长度、尾随字节、零token、零任务ID、INT_MIN、正值边界、遥测周期、参数重复/未知ID/type/范围错误；Qt与通用核心使用契约，实际P9使用相同版本。
3. P9真实uart_protocol集成测试覆盖11个命令合法载荷返回UNSUPPORTED，非法载荷先返回3/4，未知及事件号请求返回2；没有状态/目标/邮箱副作用。
4. 回归跨token HELLO接管、待处理接管、运行禁止接管、相同帧去重、同SEQ异内容、序号回绕、STOP优先、心跳保护、完成后才应答及能力0x180。
5. 副本内容不一致时检查失败；既有Qt软件测试、P9 UART/控制服务及诊断TX/echo回归通过。硬件用例未跑必须明确跳过，不沿用旧计数。
6. 使用既有ARMClang编译受影响单元并链接正常候选，记录代码/RAM/栈及警告。增加公共头文件不要求修改构建工程；若发现必须改变HAL/构建系统/链接配置，停止本范围并另行评审。
7. 更新进度、功能边界及协议手册的实现说明；设计未实现前不得改9/11支持数量或宣称功能完成。

## 9. 交付和后续阶段

第一轮交付为契约头文件及受校验的分发副本、三个接入点、独立和实际P9回归、一致性检查、构建/栈记录、同步文档。当前仅书面设计已形成，尚无这些产品交付。

书面设计通过后再细化实施计划并执行。后续运动、参数保存和校准分别设计；正常模式硬件安全验收仍是开放实际运动的前置条件，不被本轮框架整理替代。
