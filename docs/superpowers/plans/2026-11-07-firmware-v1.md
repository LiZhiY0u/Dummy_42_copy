# Original firmware integration v1

Goal: Deliver a buildable original-based STM32F103CBT6 firmware for hardware tests, preserving original pins/control tuning and adding P9-style UART and bounded encoder failure handling.

Architecture: Preserve EncoderBase/DriverBase abstractions. Stop and latch encoder faults; commands cannot restart a faulted motor until reset. Validate communication before mutating control. Defer UART parsing and telemetry to foreground. Store calibration integrity metadata in its own page immediately before the existing calibration table, and reserve both from the linker. Existing calibration without metadata must be redone. Configuration is versioned/CRC checked; legacy configuration resets to defaults.

Execution: implement inline in existing isolated checkout; no worktree, no push or environment publication.

- [x] Add host tests for real encoder SPI failures/parity/no-magnet and protocol payload/number validation; observe failures before implementation.
- [x] Add bounded SPI, sample validity, latched motor fault and calibration abort; verify host tests.
- [x] Validate CAN/text/binary inputs, repair CAN 0x06 and configured node routing, defer UART work, protect DMA buffers; verify protocol tests.
- [x] Reserve Flash metadata/table/config regions; verify erase/program results, CRC and commit marker before accepting calibration, store versioned config only while stopped.
- [x] Build firmware, run all host tests, inspect diff, package source patch and firmware with protocol and hardware-test instructions.

Review focus: no PWM after encoder faults; short/malformed/non-finite inputs cannot mutate goals; calibration/config writing occurs with motor stopped; DMA source immutable while busy; cold boot cannot accept incomplete calibration or legacy config. Host tests cannot replace measurement of 50us ISR timing, actual Flash interruption, driver signals and motor dynamics.

## Verification and review ledger

- Encoder test first reproduced stale valid angle after parity failure (assertion failure), then passed after invalid-sample handling.
- Timing test first reproduced NaN time acceptance, then passed after finite/positive validation and stable bounded velocity calculation.
- Maintenance test first required missing Begin/EndMaintenance behavior, then passed with attempted re-enable during and after maintenance.
- Final host suite: six native executables, all pass; ARM MinSizeRel clean build from tools/build_firmware.sh passes.
- Independent reviewer found flash/button race (fixed with maintenance lock), RX-idle aborting TX (fixed with RX-only abort), and full RX DMA loss (fixed with chunk completion rearm and error resync). UART pipeline tests cover a 130-byte burst, immutable DMA source while busy and overrun recovery.
- Ruling: Faults latch until reset rather than automatic retry into active output; hardware operator must explicitly restart after correcting faults.
- Ruling: Reserve an extra 1 KB metadata page, reduce application limit to 94 KB, reject old calibration/config formats and require recalibration. Cost: first upgrade resets custom configuration and requires a calibration session.
- Ruling: Keep original default tuning/pins, and retain P9's no-CRC frame format for compatibility. CRC transport framing and communication-loss stop remain future work; current protocol cannot guarantee integrity under arbitrary line noise.
- Ruling: Configuration storage is one CRC-protected page with readback; torn writes restore defaults, not the previous configuration. Dual-page retention is outside this first hardware-test release.
- Hardware validation remains outstanding: ISR timing, actual SPI mode/timing, driver current, Flash power loss, real DMA/IRQ behavior, motor dynamics and temperature.
