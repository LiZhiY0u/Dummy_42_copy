# 文档维护与持续记录规则

生效日期：2026-10-03。用户要求：整理本任务进度、功能说明、协议手册等，并随实际进度更新。

## 文档分工

| 文档 | 保存内容 | 更新触发点 |
| --- | --- | --- |
| `README.md`、`docs/README.md` | 简短入口及阶段摘要 | 阶段切换、主要入口/构建目录变化 |
| `docs/项目进度记录.md` | 当前台账、问题、最多三项下一步及追加历史 | 每次有实质推进、失败或验证结果 |
| `docs/功能说明.md` | 实际可用功能、使用步骤及限制 | 界面/后端能力、运行流程或环境变化 |
| `docs/protocol/串口协议V1使用手册.md` | 用户对接说明与当前实现范围 | 命令、字段、状态码、时序、能力位或实测范围变化 |
| `docs/protocol/serial-v1.md`、`golden-frames.json` | 设计基线及独立向量 | 线格式/命令契约变化；必要时变更 revision |
| `docs/validation/`、日期化加固记录 | 验证条件、命令、结果、失败及证据边界 | 新测试、构建、烧录、实机联调 |
| `docs/实施计划.md` | 分阶段验收门槛和工作清单 | 调整范围、完成计划项或发现新依赖 |

本规则已写入根目录 AGENTS.md，供后续继续本工作区时读取。不创建定时任务，不在无人工作时猜测进展，也不自动扫描其他聊天或承诺外部修改实时同步。

## 每次工作结束前

1. 先核对实际代码、Git、运行配置与测试证据，再修改当前台账。
2. 区分“已定义”“已实现”“软件测试通过”“诊断实机通过”“正常模式实机通过”。记录测试所用固件模式、连接、是否发送使能/运动。
3. 更新受影响的功能与协议说明；未受影响的文档不为改日期而重写。
4. 在台账追加本次历史，保留旧结论并标记修订，不能把未验证项改成完成。
5. 核对相对链接、文件路径、命令、状态码和验证计数；检查工作区改动，不自行提交/推送或清理用户文件。

字段布局只在协议文档维护完整定义，其他文档链接引用；台账保存当前状态，日期化记录保存当时证据。计划中的频率、限值或特性不当作实测事实。线协议版本、协议 revision、参数 schema、固件构建标识分别记录。

## 执行记录模板

```text
日期与阶段：
用户目标/本次范围：
改动文件和行为：
验证命令、条件及结果：
失败/原因/处理：
实机条件（端口、固件模式、烧录、使能/运动与否）：
尚未验证与风险：
提交/推送状态（确有提交才写 ID）：
下一步（最多三项）：
```

日志或构建产物可能被覆盖，应把必要摘要、配置和稳定证据标识写入记录。若没重新跑测试，写“核对既有日志”，不能冒充本次新通过。
