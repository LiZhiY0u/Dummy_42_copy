## 1. 目标、假设和代码依据

目标：基于已有闭环步进电机固件，开发可连接、可控制、可观察、可定位故障的 Qt 串口调试上位机。

第一版暂按 Windows、USB 转串口、单电机调试和参数整定设计；通过设备信息识别单个设备，不在第一版实现多轴同步。采用已检查的 Qt 5.14.2、Qt Widgets、Qt SerialPort、MinGW 7.3.0 64 位与 qmake，不要求安装新工具。上位机工程位于本项目的 `host/`，实施计划与持续进度记录见同目录下的文档。

已检测环境：Qt 安装于 `E:\qt`；Qt Creator 4.11.1；Qt 包含 MinGW/MSVC 的32/64位套件。64位qmake与MinGW编译器版本查询成功，QtSerialPort头文件、导入库和DLL存在。Qt Creator当前默认Kit为MSVC 2017 32位；本项目应显式选择MinGW 7.3.0 64位Kit，不改变全局默认设置。完整工程编译、链接与运行尚未验证。

已读取用户引用的“下位机”任务，并核对本地 `Dummy_42_copy/demo/P9.cbt6_motor_qt` 源码，Git HEAD 为 `05c6690b3704a0925cee8bb3032b18d840bc9db9`。本地另有 Keil 工程和构建输出改动，未改动这些文件。本方案依据源代码，不将构建产物视为协议实现证据。

确认的现状：

- 硬件为 STM32F103CBT6、MT6816、TB67H450；现有 USART1 为 115200、8 数据位、无校验、1 停止位。
- 内部每圈 51200 个细分单位，电流使用 mA，速度使用细分单位/s。
- `Uart/uart_handle.cpp` 收取 `AA 55 CMD H L` 五字节，位置、速度使用偏移与缩放编码；`0x22` 控制上传，当前定时器调用速度上传。
- UART 没有 CRC、事务号、错误应答；DMA 回调直接处理缓冲区的第一帧，不是完整字节流解析器。
- `Motor::Controller` 已有位置、速度、电流设定、限流、限速和规划逻辑。CAN 另有校准、DCE 参数和状态查询等命令，但这些并未全部通过 UART 暴露。
- 速度环使用 PID，位置环使用 DCE；两组参数需要分别展示。
- `STATE_FINISH` 主要根据规划软目标判断，不等于编码器实际到位。
- `GetFocCurrent()` 返回控制算法给出的电流指令，没有证据表明这是 ADC 实测相电流。
- 编码器错误会休眠，但当前代码不具备本设计要求的统一故障锁存和显式重新使能机制。
- CAN 设置 `CONFIG_COMMIT` 不等于完成持久化；当前主循环未看到完整的配置提交消费者，启动参数仍在主程序中赋默认值。保存配置功能必须补齐并验证。
- 校准表缺少 CRC 和原子提交；写 Flash 返回值不足，不能把当前“校准结束”直接宣传为“数据已可靠保存”。

## 2. 方案选择

| 方案 | 优点 | 局限 | 判断 |
|---|---|---|---|
| 自定义二进制协议 | 能直接表达运动任务、遥测、错误与版本；报文紧凑 | 需要实现两端编解码 | 推荐 |
| Modbus RTU | 可用标准工具，适合 PLC/寄存器集成 | 运动任务和主动遥测需要额外约定 | 若以工业集成为主再选 |
| 延续五字节协议 | 最快连接旧固件 | 缺少可靠性与扩展信息 | 仅作为明确选择的旧协议模式 |

Qt 界面推荐 Widgets，适合表格、参数页和仪表式调试。QML 可用于未来强调动画和触摸的产品界面，但当前没有必要同时维护两套 UI。

新固件使用下述协议，旧固件使用独立 LegacyAdapter。协议模式由用户显式选择；不能为了自动探测向旧固件发送新帧，因为同样的 `AA 55` 帧头可能被旧解析器误解释成运动命令。旧模式仅开放实际已有的功能，标明缺少应答与校验。

## 3. 串口协议 V1 建议

### 3.1 链路和帧结构

默认 115200 / 8N1 / 无流控。TTL 电平、共地及引脚须对照实际板卡确认，不能将 RS-232 电平直接接 MCU UART。第一版为点对点，不定义串口广播运动命令。

| 偏移 | 字段 | 长度 | 定义 |
|---:|---|---:|---|
| 0 | SOF | 2 | `AA 55` |
| 2 | VERSION | 1 | `01` |
| 3 | TYPE | 1 | `01` 请求，`02` 应答，`03` 事件，`04` 遥测 |
| 4 | LENGTH | 2 | 仅 Payload 字节数，0～128 |
| 6 | SESSION | 4 | 当前连接会话标识 |
| 10 | SEQ | 2 | 请求事务号，应答原样回传 |
| 12 | CMD | 2 | 命令号 |
| 14 | PAYLOAD | N | 命令数据 |
| 14+N | CRC | 2 | CRC-16/CCITT-FALSE，低字节先发 |

总长 `16 + N`，最长 144 字节。所有多字节字段使用小端序；有符号整数采用二进制补码。禁止直接发送 C/C++ struct 内存，禁止依赖 Qt QDataStream 的默认版本、字节序或 bool 大小。

CRC：poly=`0x1021`、init=`0xFFFF`、RefIn=false、RefOut=false、XorOut=`0x0000`；覆盖 VERSION 至 Payload 最后一个字节，不包含 SOF 和 CRC。标准输入 `123456789` 的校验结果应为 `0x29B1`。

CRC 错、长度超限、非法 TYPE 的帧丢弃并计数，不执行指令。不为未验证的损坏帧发送错误应答，避免误用损坏的 SEQ。有效但不支持的命令返回明确错误。

### 3.2 会话、应答和重试

连接流程：打开串口 → HELLO → GET_INFO → GET_STATUS → READ_PARAMS → 开启遥测 → 用户显式使能。

- HELLO 请求头 SESSION=0，Payload 为上位机新生成的非零 uint32 会话值；下位机仅在驱动禁用时接受新会话，并在应答头回传该值。此值用于区分连接，不提供身份认证。
- 下位机重启后会话失效、驱动禁用；除 HELLO 外拒绝旧会话请求。Qt 每次重新握手生成新值并清空事务队列。
- SEQ 请求范围 1～65535，回绕时避开未完成事务；遥测/事件使用独立计数，不与请求应答配对。
- 所有应答 Payload 以 uint16 STATUS 开头；其后为命令定义的返回数据。成功应答返回实际接受的值，界面不能仅凭按钮点击更新设备状态。
- 普通命令同一时刻最多一个待应答事务；STOP/DISABLE 可优先发出，取消尚未发送的运动请求。
- 建议普通应答超时 200 ms；只读查询最多重试一次，同 SESSION、SEQ、CMD、Payload。校准、保存、相对位移等操作不自动重试。
- 下位机为最近少量事务保存请求指纹与结果；同事务、同内容返回缓存结果，不能重复执行；同事务、不同内容返回事务冲突。缓存大小和存活期在实现前根据 RAM 预算确定。
- 长任务先返回 STATUS=ACCEPTED 与 uint32 task_id，再通过事件和查询报告进度。task_id 只在当前 SESSION 有效。
- 超时表示结果未知，Qt 查询实际状态；不能将它等价为执行失败，也不能直接重发运动。

建议 STATUS 编号：0 OK，1 ACCEPTED，2 UNKNOWN_CMD，3 BAD_PAYLOAD，4 OUT_OF_RANGE，5 WRONG_STATE，6 NOT_CALIBRATED，7 ENCODER_FAULT，8 BUSY，9 STORAGE_ERROR，10 UNSUPPORTED，11 BAD_SESSION，12 SEQ_CONFLICT，13 INTERNAL_ERROR。

### 3.3 数值单位

| 物理量 | 线上的表示 | UI 转换 |
|---|---|---|
| 位置 | int32 细分单位 | 圈=值/51200；角度=值×360/51200 |
| 速度 | int32 细分单位/s | rpm=值×60/51200 |
| 加速度 | uint32 细分单位/s² | 圈/s²=值/51200 |
| 电流指令/限流 | int32/uint32 mA | A=值/1000 |
| 持续时间、时间戳 | uint32 ms | 明确区分设备时间和电脑时间 |
| PID/DCE 系数 | int32 | 保持现有算法整数及缩放意义 |

线上的位置不使用角度 float，也不使用 3000/5000 等偏移表示负数。GET_INFO 返回 `units_per_rev`，UI 不把 51200 写死在各个页面。

所有参数在上位机和下位机两端校验；下位机为最终裁决者。位置差、偏移累加和单位换算使用更宽的中间整数并检测 int32 溢出。多圈计数来自运行时累计，不代表断电后可保留的绝对多圈位置。

### 3.4 命令集合

以下为设计编号，不沿用 CAN 命令号，减少接口耦合。`u32/i32/u16/u8` 均为固定宽度整数。

| CMD | 命令 | 请求 Payload | 行为/返回 |
|---|---|---|---|
| 0x0001 | HELLO | u32 新会话 | 协议版本与当前会话 |
| 0x0002 | GET_INFO | 空 | 固件/硬件版本、UID、能力位、units_per_rev、合法范围 |
| 0x0003 | GET_STATUS | 空 | 状态快照，字段同遥测 |
| 0x0004 | HEARTBEAT | 空 | 续期当前控制会话，回传设备运行时间 |
| 0x0101 | ENABLE | u8 mode | 模式：0位置、1速度、2电流；从安全初始目标进入 |
| 0x0102 | DISABLE | 空 | 禁用输出、清理目标与积分，取消未完成运动 |
| 0x0103 | MOVE_ABS | i32 position,u32 max_velocity,u32 acceleration | 绝对位置任务，返回 task_id 与接受值 |
| 0x0104 | SET_VELOCITY | i32 velocity,u32 acceleration | 速度目标，允许负速度 |
| 0x0105 | SET_CURRENT | i32 current_mA | 电流指令目标，受设备限流约束 |
| 0x0106 | STOP | 空 | 优先禁用输出，返回真实状态 |
| 0x0107 | SET_ZERO | 空 | 禁用且静止时设置当前逻辑零点，仅 RAM 生效 |
| 0x0108 | CLEAR_FAULT | 空 | 条件恢复后清锁存；仍保持禁用 |
| 0x0201 | READ_PARAMS | 空 | 带参数 schema_version 的参数列表 |
| 0x0202 | WRITE_PARAMS | 参数条目列表 | 整批校验、整批生效，返回 revision 与实际值 |
| 0x0203 | SAVE_PARAMS | u32 revision | 禁用时持久化指定已生效版本；成功须回读校验 |
| 0x0301 | CALIBRATE_START | 空 | 禁用状态下启动，返回 task_id |
| 0x0302 | CALIBRATE_QUERY | u32 task_id | 阶段、进度、错误、保存验证结果 |
| 0x0303 | CALIBRATE_CANCEL | u32 task_id | 请求取消；驱动立即休眠，存储收尾结果另报 |
| 0x0401 | TELEMETRY_CONFIG | u16 period_ms | 0关闭；其余支持10/20/50/100，回传实际周期 |
| 0x0402 | TELEMETRY | 无请求 | TYPE=04，周期状态快照 |
| 0x0501 | TASK_EVENT | 无请求 | task_id、事件、结果、设备时间 |
| 0x0502 | FAULT_EVENT | 无请求 | 新增故障位、设备状态、设备时间 |

MOVE_ABS 在已使能的位置模式下执行；SET_VELOCITY/SET_CURRENT 要求相应模式。切换模式必须先禁用，避免旧目标意外接管。位置模式使能时锁存当前位置为初始目标；速度/电流使能时初始目标为零。

DISABLE 和 STOP 在任何有效会话状态下可重复执行；STOP 同时取消校准运动。它是软件停机，断线时无法保证指令抵达；UI 不宣称其为硬件急停。受控减速停车、保持力矩和硬件急停属于不同语义，后续新增命令必须分别定义。

相对移动第一版由 UI 转为绝对目标前先获取新鲜位置，并显示最终目标；若需要严格的相对移动原子语义，再新增带去重机制的下位机命令。定时到位暂不开放：现有 SetPositionSetPointWithTime 在时间不可达时仍可能设定位置目标，必须先改成失败不改变目标。

参数条目格式建议：`u16 schema_version,u16 count`，之后重复 `u16 id,u8 type,u8 length,value`。V1 type 固定为 i32/u32/u8，分别长4/4/1；未知ID、错误长度、重复ID、超范围均整批拒绝。Payload 不得超过128；跨多帧批量提交属于未来扩展。

参数第一批包括限流、限速、加速度、校准电流、速度PID的kp/ki/kd、位置DCE的kp/kv/ki/kd、堵转保护开关。运行中第一版拒绝写参数，先保证可预测性。系数合法范围不能凭现有默认值推定，需结合算法中间乘法与溢出范围确定。

### 3.5 遥测与到位判定

固定遥测 Payload 为48字节，按顺序：

`u32 timestamp_ms, u32 sample_counter, i32 position, i32 target_position, i32 velocity, i32 target_velocity, i32 current_command_mA, i32 target_current_mA, i32 position_error, u32 fault_bits, u8 state, u8 mode, u8 calibrated, u8 encoder_valid, u16 encoder_error_count, u16 tx_drop_count`。

字段来自同一控制快照；无法采集的字段通过能力位说明，不以0伪装实测结果。GET_STATUS 使用同样快照，前置应答 STATUS 后共50字节。

建议默认50Hz：每帧64字节，50Hz约3200B/s；8N1下115200波特率约11520B/s，单向遥测占用约28%。100Hz约56%，仅用于短时整定。UI绘图固定20～30Hz刷新，采集与绘图不同频率。20kHz控制环的数据如需分析，未来考虑板端触发、有限长度捕获后分块下载。

位置任务完成必须同时满足：规划已结束、实际位置误差在容差内、实际速度在阈值内，并连续保持一定时间。容差、速度阈值和保持时间通过设备参数公布；具体数值需结合机械负载和实际测试确定。任务具备超时、取消、故障终止结果，不能永久只显示“运行中”。

速度模式到达目标仅表示稳速，不表示运动结束。电流显示始终标注“指令电流”；后续若增加实际采样，分配独立字段。

### 3.6 字节流解析规则

两端采用累计缓冲区：找AA55 → 等待14字节头 → 检查版本/类型/长度 → 等完整帧 → 验CRC → 分发 → 继续解析余下字节。

CRC失败从当前候选帧起点向后移动1字节重新搜索；合法Payload内出现AA55不影响完整帧解析。半帧超过建议100ms仍未补齐则丢弃候选并重新同步；长度限制避免错误LEN无限等待。Qt的readyRead、MCU的DMA IDLE都只能说明收到一些字节，不能作为协议帧边界。

验算样例：会话0x11223344、SEQ=1、MOVE_ABS、目标51200、限速51200、加速度102400：

`AA 55 01 01 0C 00 44 33 22 11 01 00 03 01 00 C8 00 00 00 C8 00 00 00 90 01 00 FC A7`

CRC计算值0xA7FC，线上FC A7。此样例仅说明编码，实际执行还需会话、使能和模式满足条件。

## 4. Qt 框架

```text
Widgets页面
    ↓ 业务请求 / ↑ 状态、结果
DeviceService（连接流程、能力检查、控制任务）
    ↓
SessionController（会话、事务、超时、心跳、优先队列）
    ↓
ProtocolCodec（纯编解码、字节流分帧、CRC）
    ↓
SerialTransport（QSerialPort、打开关闭、收发和错误）
    ↓
USB转串口 → STM32

DeviceService → DeviceStateModel → 页面/绘图
状态快照 → TelemetryBuffer → RecordWriter → CSV
MockTransport → ProtocolCodec（无板卡调试与错误注入）
```

模块边界：SerialTransport不理解电机；ProtocolCodec不访问Widgets；页面不拼接字节、不直接写串口；DeviceStateModel只维护设备确认的状态。

建议目录：`src/ui/`、`src/device/`、`src/transport/`、`src/protocol/`、`src/telemetry/`、`src/storage/`、`tests/`、`docs/protocol/`。

推荐线程：

- UI线程：Widgets、DeviceStateModel、曲线刷新。
- 通信线程：一个拥有事件循环的worker；SerialTransport、QSerialPort、ProtocolCodec、SessionController及其QTimer全部在该线程创建和使用。
- 数据量较大时单独记录worker：批量写盘，使用有界队列；小规模第一版可先使用异步批处理。

跨线程只通过queued signal/slot传递值对象，不传递缓冲区裸指针。QSerialPort用readyRead异步接收；不在UI线程调用waitForReadyRead或阻塞式等待。接收缓存、曲线历史、日志和写盘队列全部设上限，长时间运行不无限增长。

串口write成功仅表示进入发送流程；处理部分写入与bytesWritten，命令成功以协议应答为准。STOP可越过应用层普通待发送命令，但不能跳过已经进入操作系统/串口的字节。通信层限制积压，禁止把大量运动帧预先写入系统缓冲。

此前框架讨论参考了Qt官方的QSerialPort、Threads and QObjects、Serial Terminal文档。实施目标已调整为Qt 5.14.2；接口可用性以本机Qt 5.14.2头文件、随安装的文档与编译结果为准，不使用Qt 6专属API。

## 5. 下位机框架与安全状态

DMA接收 → 有界接收环形缓冲 → 主循环分帧/CRC → CommandDispatcher → 命令邮箱 → 20kHz边界应用 → 状态快照 → 主循环打包 → TX队列/DMA发送。

UART ISR仅搬运字节、记录错误和重启接收，不解析完整命令、不写Flash。控制ISR只执行固定开销的控制、安全状态和邮箱应用，不做CRC、报文打包或日志格式化。参数集采用双缓冲/版本切换；控制快照使用短临界区或双缓冲，禁止整个打包过程关闭中断。

建议状态：DISABLED、READY、RUNNING、CALIBRATING、FAULT。未校准作为单独状态标志；禁止使能但允许合法的显式校准。

- 上电、重连后均保持DISABLED，不恢复历史运动队列。
- Qt建议100ms心跳，下位机建议500ms未收到当前会话心跳时锁存通信失联并禁用输出。只由有效HEARTBEAT续期，不由遥测、坏帧或旧会话续期。
- 编码器异常、堵转、通信失联均按故障策略关闭输出，故障恢复后也不自动继续旧运动。清故障与使能必须分开。
- CALIBRATING也受通信看门狗约束；取消/失联先停止驱动。Flash阶段必须划分可服务通信的步骤或公布BUSY与受控维护窗口，不能用阻塞保存使看门狗误触发，也不能无条件关闭看门狗。
- SAVE_PARAMS/CALIBRATION只有驱动停止才允许进入存储步骤。必须报告擦除、写入、回读与CRC验证失败；保存结果不能只表示收到请求。
- 参数存储增加版本、长度、CRC与提交状态。若Flash预算允许，采用双槽提交；校准表空间较大，应先核对链接布局再选存储方案。
- 多个控制入口（UART、CAN、按键）共用控制服务和状态规则；活动UART控制会话期间，其他入口只能停机，不能暗中修改运动目标。未来需要CAN控制时增加显式控制权转移。

建议先评估512B RX ring、最大144B帧缓冲、独立且发送期间不可改写的TX缓冲及小容量去重缓存，总额以链接map核算。环形缓冲溢出时丢弃并重新同步、记录计数；不能继续解析已被覆盖的数据。遥测拥堵丢弃旧快照，应答和故障事件优先；事件丢失仍可通过状态查询发现故障。

## 6. 界面与功能优先级

固定顶部：端口、连接状态、设备ID、固件版本、协议模式、使能状态、通信延时。全局停止按钮常驻；未握手或状态过期时禁用运动入口。

| 页面 | 第一版必要功能 |
|---|---|
| 连接与概览 | 端口枚举/刷新、串口参数、握手、设备能力、故障摘要、数据新鲜度 |
| 运动控制 | 位置/速度/电流模式、显式使能/禁用、绝对目标、限速/加速度、零点、任务结果 |
| 参数整定 | 读取、编辑、范围与单位提示、RAM应用、应用前后对比、显式保存、回读确认 |
| 实时曲线 | 目标/实际位置、位置误差、目标/估计速度、指令电流；暂停显示、缩放、游标 |
| 校准与诊断 | 校准阶段/错误/保存状态、故障清除、编码器有效性、丢帧/CRC/溢出计数 |
| 日志与记录 | 结构化命令/应答日志、CSV采集、原始帧查看、文件分段与记录失败提示 |

CSV至少包含电脑接收时间、设备时间、sample_counter、位置/速度/目标、指令电流、状态与故障。附带设备ID、固件与协议版本、参数快照和采样周期。断流留空或标记，不补造数据。

参数文件使用带schema和设备适用信息的JSON；导入后先显示差异与越界项，不自动写设备。保存与导出为两种按钮，避免用户误解为都已经写入Flash。

连接断开后曲线可保留，但数值标记过期；恢复连接重新读取状态和参数。正常退出尝试禁用，失败由设备看门狗兜底。不能把关闭窗口视为设备已确认停机。

后续功能：有限次数的阶跃响应与往返实验、任务脚本、板端高速捕获、多电机列表、CAN桥接。自动PID整定、固件升级、云服务、复杂插件系统暂不进入第一版。实时温度/母线电压/实际电流需要硬件采样支持，当前不承诺。

## 7. 实施顺序与验收

1. 协议与控制安全：确定报文和数值边界，固件增加流解析、应答、快照、使能/停机和心跳。Qt先用MockTransport完成连接状态机。
2. 最小运动闭环：握手、状态读取、显式使能、速度/位置控制、停止、断线保护。低电流空载联调后再增加电流模式。
3. 调试工具：50Hz曲线、记录、参数读取/RAM应用和故障显示。
4. 持久化和校准：补齐存储失败反馈、回读/CRC、校准进度和取消，再开放“保存到设备”。

必要验证：两端共享黄金帧；任意字节拆包、多个帧粘连、噪声、错CRC、超长LEN、截断帧与重同步；事务重复/冲突/超时/重连/设备重启；负目标、越界和运算溢出；校准中取消、Flash失败与断电；实际到位而非仅规划完成；Qt录制和绘图同时运行时的响应。

硬件验收尤其包括：拔掉USB或结束上位机进程后设备按设定看门狗期限停止；编码器恢复后保持禁用；串口/遥测压力下20kHz控制周期仍满足实时预算。停机、应答和波形采样延时必须测量后报告，不凭框架推断保证。

初次设计仅完成文档，没有修改固件、创建Qt代码、安装环境、提交或推送。后续实施状态以《项目进度记录》为准；原始设计事实保留，变化另记。
