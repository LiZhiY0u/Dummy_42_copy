# 2026-11-08 控制周期内部校准请求接入

本轮将前一批任务记录接入P9 UART后端内部，不对外启用CALIBRATE_START，不实际校准。main28c40a6上累计未提交变更，板上仍79182D...编码器候选。

## 新实现

- 私有queueCalibrationStart只在有效会话、当前样本有效、无故障且禁用、电流1..1000mA、没有待启动/活动校准任务时接受。接收时仅创建任务及待处理请求，不置isTriggered。
- 控制服务周期先执行既有邮箱（含STOP），之后重新验证待处理启动的实时状态。STOP会取消待启动任务，因此同周期不可能先STOP后又启动；超时导致会话失效的请求也不能启动。
- 通过后在控制周期重置校准的必要标量状态，记录所属会话、任务进入采集，再最后置isTriggered。不要求已有校准表，但必须有有效实时采样；这不是允许绕过普通闭环ENABLE的校准检查。
- 既有取消驱动同步取消当前任务并清待启动标志。旧校准器触发自行消失但没有明确存储验证时记录失败13（传感器无效时7），绝不猜测成功；后续真正的存储验证/完成接入仍待做。
- 主循环提交内部请求用已有ARM临界区保护；控制周期为状态变更单一执行者。没有增加公共ControlService枚举、改HAL/IRQ调度/协议布局。

## 验证

新增测试先编译失败：内部queue接口/任务变量尚不存在；同时发现替身Motor聚合初始化新增config字段告警，之后给替身补构造函数，不改产品类型来迁就测试。

新编译MinGW真实P9 UART/protocol/control_gate/control_service集成，四个内部启动场景及既有场景共16场景全退出0；同轮运行已有任务记录、电流测试均通过（未冒称新编译两者）。场景包括未校准但实时采样有效、非法session/current/sensor拒绝、重复请求BUSY、接收不输出、STOP/超时优先、无验证完成不报成功。

正常配置Keil全量构建：0错误/0告警，Code46592/RO5348/RW92/ZI8732；对前轮电流保护Code+28/RO+4/ZI+112。静态栈992/1024B、MinimumHeadroom32通过。[全量日志](evidence/2026-11-08-calibration-start/full-build.log)。正常对外命令仍不引用queueCalibrationStart，目标链接器可去除未引用入口；不能用此次构建宣称UART启动已可调用。
