# 2026-11-08 校准Flash写入结果与取消收尾

范围：真实EncoderCalibratorBase::TickMainLoop配RAM映射Flash替身。没有执行硬件Flash、烧录或运动，对外校准启动仍未开放。

## RED与修复

先构造有效200步正反向样本，旧主循环可生成16384个表项；故障注入第10次写入游标越界后，旧实现仍将rectifyValid置真，RED退出1。新增逐半字边界/游标前后进度/物理地址回读检查后，七类故障场景通过。

产品变更仅Encoder/encoder_calibrator_base.cpp：

- 写入前保持驱动休眠、RAM校准有效位置false；进入计算必须仍触发且状态为计算。
- 擦除结束检查取消，开始写入后检查整个表区已擦为FFFF。
- 每半字检查索引<16384、值<51200、游标等于预期地址；调用旧void写入API后检查游标恰增2及物理内存回读相等。失败或取消立即跳统一收尾，不继续写。
- Begin后的各分支End恰一次；失败不再触发第二次整区擦除。擦除期间取消不再进入Begin。
- 主循环显式用volatile视图重新读取IRQ可能修改的触发/状态，不改公开字段类型。最终RAM有效位与取消条件在短PRIMASK临界区内一并判断，不把延迟完成覆盖成成功。
- 写入过程对预期数据累计CRC32（初值FFFFFFFF、多项式EDB88320、低字节先行）；结束再读取整表累计比较。没有把CRC持久化到Flash，也没有新增断电提交格式。

仅逐半字回读时，新增“End后早先表项损坏”测试再次RED退出1；补整表CRC后GREEN。CRC用于本次内存一致性校验，不替代持久化提交标记。

## 本轮新跑测试

新编译真实校准主循环测试，成功写满16384项且每项<51200；故障注入：写游标失败、即时回读损坏、写到第10项取消、End时取消、End时早先表项损坏、擦除失败、擦除期间取消。断言失败路径rectifyValid=false、结束禁用、不再输出，写入后始终收尾上锁。Flash替身仅在RAM操作，不代表实际HAL结果。

真实校准Tick电流测试因Flash替身类型更新同轮重新编译运行，通过，确认IRQ被测路径仍没有Flash调用。两测试使用既有MinGW7.3，命令在固件tests/README.md。未声称本轮重跑Qt/串口或其余旧场景。

正常Keil全量0错误/0告警：Code47076/RO5352/RW96/ZI8728。对前轮启动候选Code+484/RO+4，RW+4/ZI-4，RAM合计不变。静态栈992/1024B、MinimumHeadroom32通过。[全量日志](evidence/2026-11-08-calibration-storage/full-build.log)。

## 不得遗漏的剩余问题

1. Memory/stockpile_f103cb.c擦除仍用HAL_MAX_DELAY，且忽略部分HAL擦除返回值。本轮能发现擦除结果不符，但不能保证旧HAL调用不会挂起，也没缩短整区擦除时长。
2. 原主循环计算/Flash整体仍是阻塞阶段，UART轮询未分步；替身直接注入取消验证了标志处理，不代表真实串口STOP能在阻塞期间及时被解析。失联时间与真实Flash同bank停顿也未测。
3. 新表已写完但未完成RAM确认时断电，当前启动仍只按数值范围接受表，没有持久化CRC/提交标记；不能承诺断电事务一致性或取消后重启一定拒绝该表。旧布局尚未迁移。
4. 当前任务守卫仍将没有显式已验证生命周期的旧完成记为失败13，未接query/terminal事件。不要仅从rectifyValid推测任务完整成功。

因此下一步处理有界Flash底层/分步通信和持久化提交，再接外部分发；不以本轮结果授权实机校准。板上仍为79182D编码器候选；源码/文档未提交推送。
