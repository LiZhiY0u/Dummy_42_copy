# 基础实机验证工具准备

2026-11-10。新增scripts/check-device-basics.ps1，现有PowerShell/.NET即可使用，不安装环境。

## 默认边界

必须显式指定端口，或选择无硬件SelfTest；不默认沿用COM4/COM8。白名单仅HELLO、STOP、心跳、GET_INFO/GET_STATUS，没有通用发送参数，也没有ENABLE/清故障/校准/烧录入口。握手后先STOP，再读取状态；DTR/RTS关闭，无流控，115200/8N1。应答必须CRC、类型、会话、序号和命令均匹配。200ms超时报告结果未知，不自动重发或继续下一步。

GET_INFO能读UID与能力，但不能证明HEX身份或物理Flash容量；后者需烧录日志/哈希与调试器只读验证，不能拿能力位代替。STOP应答与禁用状态不是物理急停证明。脚本可能因握手/故障/旧固件返回不符合预期而失败，不自动清故障。

## 复现

在本项目根目录PowerShell中：

```powershell
# 不打开串口，自检CRC和解析器
& './scripts/check-device-basics.ps1' -SelfTest
# 先在设备管理器确认CH340实际COM号，关闭占用串口的上位机/调试助手
& './scripts/check-device-basics.ps1' -Port COM4
```

COM4只是命令示例，不是本轮已确认设备。运行第二条前确认接线/供电条件并准备断电；本轮没有运行该条。预期看到UID、能力、状态/编码器有效位/故障原始值以及PASS。失败则保留输出，不自动烧录/校准；停止不确定时使用已准备的物理断电手段。

## 本轮证据

SelfTest通过CRC标准向量123456789→29B1、噪声与半帧、坏CRC后重同步和命令白名单。首次数组切片为Object[]导致AddRange类型错误，显式byte[]转换后重跑通过，未隐藏失败。

串口枚举返回COM1/6/10/9/5/4；Get-PnpDevice名称识别报CIM资源无法访问，不能确认CH340/STLink在线，也不能据枚举确认目标端口。未打开串口、烧录、运动或实机验证。本轮未运行Qt/ARM/固件测试，产品候选仍前轮7D5932DF，未提交推送。

下一步用户确认当前硬件接好/实际端口后执行基础检查，记录身份/状态/STOP；通过后再安排授权烧录和独立低电流校准。当前脚本刻意不包含校准操作。
