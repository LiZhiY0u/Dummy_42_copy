# 真实位置规划器与任务状态离线联动

2026-11-10。仍为离线范围，无硬件/串口/烧录/实际运动。探针电压异常继续保留。

检查实际控制器源码：位置模式消费MotionPlanner::PositionTracker的go_location/go_velocity，SetPositionSetPoint只设goalPosition（还叠加homeOffset），没有独立任务完成事件。StopAndReset会清目标/软目标/积分并Sleep。本轮没有直接改这些控制器函数。

新增PositionMove::observePlan：仅在当前目标的CalcSoftGoal已执行后，用规划位置等于目标且规划速度0通知规划完成，不能使用NewTask后尚未更新的旧输出。新增position_planner_integration_test，链接真实motion_planner.cpp及control_gate.cpp，不重写规划算法。

测试按真实规划器20kHz/50us调用，任务测量每20次（1ms），心跳每100ms。测试限值1000细分步/500细分步每秒/1000细分步每秒平方及容差等仅夹具，不是批准实机限值。实际反馈由测试刻意设置20步落后，规划完成后再延迟50ms模拟到位，验证不能提前成功。

本轮新编译-Wall -Wextra -Werror，四场景通过：

| 场景 | 规划调用次数 | 结果 |
|---|---:|---|
| 正向1000 |52959|规划完成后等待实际到位 |
| 反向1000 |52959|同上 |
| 200ms STOP |3999|先取消，再停止规划调用 |
| 500ms失联 |9999|Gate锁故障4、任务失败、不续转 |

首轮“速度不应反向”断言失败，既有规划器可能越过目标后反向修正；该单向假设不属于原协议要求，修正测试以速度绝对值不超过500和最终收敛为准，没有改变规划器实现。此处不宣称验证了严格位置无过冲或加速度全程界限。随后重新编译任务核心单元测试也通过。
